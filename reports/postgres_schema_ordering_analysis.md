## Finding

The original failing statement was statement **4** in the previous `reports/postgres_generated_schema.sql`:

```sql
CREATE TABLE IF NOT EXISTS audit_logs
                     (id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
                      timestamp TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
                      company_key TEXT,
                      user_role TEXT,
                      action TEXT,
                      module_name TEXT, details TEXT, ip_address TEXT, branch_id TEXT, action_type TEXT, document_ref TEXT, before_after_summary TEXT, event_id TEXT,
                      FOREIGN KEY (company_key) REFERENCES companies(key));
```

In the failed artifact, `companies` was not created until statement **14**:

```sql
CREATE TABLE IF NOT EXISTS companies
                     (key TEXT PRIMARY KEY,
                      name TEXT,
                      tin TEXT,
                      sub_admin_key TEXT,
                      staff_key TEXT,

                      subscription_end_date TIMESTAMPTZ,

                      created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP,
                      updated_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP, contact_email TEXT, barcode_input_source TEXT DEFAULT 'Keyboard Entry', number_of_branches INTEGER DEFAULT 1, max_branches INTEGER DEFAULT 1, branch_price_per_month NUMERIC(18,2) DEFAULT 0.0, subscription_expiry TEXT, phone_number TEXT, physical_address TEXT, industry TEXT, currency TEXT DEFAULT 'GHS', logo_url TEXT);
```

## Root Cause

`postgres_schema_generator.py` sorts table inventory alphabetically:

```text
parse_schema_compatibility_report(...) returns sorted(tables, key=lambda table: table.name)
```

That alphabetical order places `audit_logs`, `bank_accounts`, `branch_module_grants`, `branches`, `cashier_closings`, and `chart_of_accounts` before `companies`, even though those tables declare foreign keys to `companies`.

PostgreSQL validates referenced tables when `CREATE TABLE ... FOREIGN KEY ... REFERENCES ...` is executed. Because `companies` does not exist yet, statement 4 fails before the later `CREATE TABLE companies` statement is reached.

## Corrected Ordering Plan

Implemented fix:

1. Generate all table creation statements in dependency order instead of alphabetical order.
2. Keep `BEGIN` first and `COMMIT` last.
3. Emit parent tables before child tables.
4. Keep commented index placeholders as comments after table creation, or move future executable indexes after all tables.
5. If cyclic FKs are introduced later, emit tables first without cyclic constraints and add those FKs in a second `ALTER TABLE ... ADD CONSTRAINT` phase.

## Generator Change

`postgres_schema_generator.py` now makes `render_schema_sql()` receive tables sorted by topological dependency order rather than by table name. The dependency source is `TableInventory.foreign_keys`.

Algorithm:

1. Build a graph where each table points to the tables it references.
2. Topologically sort so referenced tables come first.
3. Preserve deterministic alphabetical order among currently ready tables.
4. Detect cycles and report them as manual review blockers.
5. Render tables in the dependency-safe order.
