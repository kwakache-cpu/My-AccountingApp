# PostgreSQL Migration History Design

Phase: 5B.14C

Design-only artifact. This document defines the future PostgreSQL migration history model for staging deployment execution. No SQL execution, Supabase connection, schema deployment, runtime enablement, data migration, or SQLite behavior change is included.

## Purpose

The PostgreSQL deployment executor needs an auditable history of deployment runs and phase-level events. The history model must be separate from SQLite migration metadata and must support dry-run planning, future staging execution, failure recovery, rollback tracking, and post-deployment validation evidence.

## Table: postgres_migration_history

Future table for phase-level deployment events.

| Column | Proposed Type | Required | Notes |
|---|---|---:|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | Yes | Surrogate event row identifier. |
| `deployment_id` | `TEXT` | Yes | Groups all phase events for one deployment attempt. |
| `phase_id` | `TEXT` | Yes | Phase identifier such as `Phase 1`. |
| `phase_name` | `TEXT` | Yes | Human-readable phase name. |
| `status` | `TEXT` | Yes | One of `PENDING`, `RUNNING`, `COMPLETED`, `FAILED`, `ROLLED_BACK`, `BLOCKED`. |
| `started_at` | `TIMESTAMPTZ` | Yes | Event start timestamp. |
| `completed_at` | `TIMESTAMPTZ` | No | Completion timestamp for terminal events. |
| `duration_seconds` | `NUMERIC(18,3)` | No | Duration between start and completion. |
| `error_message` | `TEXT` | No | Redacted failure summary. |
| `rollback_point` | `TEXT` | No | Named point used for recovery decisions. |
| `metadata_json` | `JSONB` | No | Artifact hashes, validation summaries, or redacted diagnostics. |

Recommended constraints:

- Primary key on `id`.
- Index on `(deployment_id, phase_id)`.
- Index on `(deployment_id, status)`.
- Check constraint for allowed status values.

## Table: postgres_deployment_runs

Future table for deployment-level summary records.

| Column | Proposed Type | Required | Notes |
|---|---|---:|---|
| `deployment_id` | `TEXT PRIMARY KEY` | Yes | Unique deployment attempt identifier. |
| `created_at` | `TIMESTAMPTZ` | Yes | Run creation timestamp. |
| `completed_at` | `TIMESTAMPTZ` | No | Run completion timestamp. |
| `status` | `TEXT` | Yes | Aggregate run status. |
| `execution_mode` | `TEXT` | Yes | `dry-run` or future `apply`. |
| `schema_version` | `TEXT` | No | Generated schema artifact version/hash label. |

Recommended constraints:

- Primary key on `deployment_id`.
- Index on `(status, created_at)`.
- Check constraint for execution mode values.

## Status Values

- `PENDING`: event is planned and has not started.
- `RUNNING`: event is in progress during a future apply run.
- `COMPLETED`: event completed successfully.
- `FAILED`: event failed before successful completion.
- `ROLLED_BACK`: event changes were rolled back or reset.
- `BLOCKED`: event was intentionally blocked before execution.

## Design Notes

- Dry-run events should use `PENDING` or `BLOCKED` only.
- Future apply events should transition through `RUNNING` before terminal states.
- Raw credentials must never be stored in `metadata_json`.
- Error messages must be redacted and suitable for reports.
- PostgreSQL migration history must not write to or depend on SQLite migration tables.

Cutover remains NO-GO until this model is implemented, deployed in staging, and validated.
